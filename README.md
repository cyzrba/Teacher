# 岗位闯关式实训平台 · 教师端

面向深圳职业技术大学人工智能本科学院的实训教学管理后台。
功能范围来自《岗位闯关式实训平台-需求确认书0706.docx》（见 `docs/`），
覆盖「数据总览 → 实训项目管理 → 岗位与技能体系 → 实训结果审核 → 学习过程统计 → 班级与任务管理 → 企业认证证书」全流程。

界面风格与学生端（`Student`，开发端口 5173）统一为**白 + 蓝**：
同一套主色、同一套状态色、同一套卡片圆角与阴影，教师端只是在密度上更接近管理后台。

大部分页面已直连真实后端（FastAPI，`/api`，见下方「真实后端对接」）：实训项目管理、
班级与任务管理、岗位与技能体系、实训结果审核、系统配置 → 更多设置，以及企业认证证书；
数据总览、学习过程统计、成长规则配置仍走本地 Mock，等各自迁移时再切换。

## 登录与角色分流

教师端对接学校统一身份认证（SSO 回调式），演示入口在 `/login`：

- 点击「教师端」→ 模拟 `?key=teacher-demo-key` 回调 → 签发 JWT → 进入 `/teacher/dashboard`；
- 直接访问 `/login?key=xxx` 会走完整回调链路；
- 若拿到的是**学生角色**，会被守卫拦回入口页并提示（演示角色分流）；
- 非教师角色访问 `/teacher/**` 一律重定向到 `/login?denied=1`。

登录态（Token / 角色 / 教师信息）落在 `localStorage`，401 时由响应拦截器清空并回到入口页。

### 技能管理（技能树 / 技能点）

「岗位与技能体系 → 技能管理」维护教师端的技能库，也就是学生端技能树的数据源：

| 区域 | 内容 |
| --- | --- |
| 左栏 · 技能体系 | 四个内置体系（光学成像系 / 传统算法系 / 深度学习系 / 项目部署系）与各体系技能点数，点击即筛选；体系是平台级字典，新增体系保留给超级管理员（接口占位），教师端不提供增删 |
| 右栏 · 技能点 | 技能点 / 说明 / 解锁说明（学生端可见）/ 前置技能 / **绑定状态** / 状态 / 操作（编辑 / 删除）；支持按名称与说明搜索、分页，并新增「只看绑定不全」筛选与数量提示 |
| 绑定状态 | 逐个技能点显示「已绑岗位 · 已绑项目」或「缺岗位 / 缺项目」（缺哪端标黄），方便老师尽快把技能点配到岗位或项目关卡上 |
| 创建位置 | **技能点只能在「实训项目管理」的关卡里、或岗位编辑里创建并绑定**；技能管理页不再提供「直接新建」，避免出现岗位与项目两端都没绑定的孤儿技能 |
| 编辑 | 说明、解锁说明、前置技能（覆盖式，后端拦自环与环路）、状态；名称全局唯一，重名会复用已有技能点 |
| 删除保护 | 被岗位或项目关卡引用时不允许删除，接口返回具体引用数量，前端提示「请先解除关联」 |
| 停用 | 停用的技能点保留在技能库中，但不再出现在新建实训项目的可选技能点里 |

### 实训结果审核的版式

分成**两个页面**（不再左右并排）：先在列表里按班级 / 学生 / 项目 / 状态找到那份实训报告，
点某一行（或「查看详情」）跳到 `/teacher/reviews/:submissionId` 查阅全部作答。

| 页面 | 内容 |
| --- | --- |
| 报告列表 `/teacher/reviews` | 表头「实训报告 + 共 N 条」；筛选条：**班级 / 学生 / 项目 / 状态**（学生下拉随班级联动）+ 只看标星；表格列：学生（含已标星标记）、班级、实训项目（第几次挑战 / 第几次提交）、提交时间、AI 总分、审核状态、及格、操作（查看详情）；底部统一分页 |
| 报告详情 `/teacher/reviews/:id` | 顶部「← 返回实训报告列表」+ 学生 · 项目；工作区 ① 逐关作答与评分 ② 评分合计 ③ 复审留痕 |

详情里的逐关卡片顺序固定：`学生作答` → `AI 评分与评语` → `教师评分与评语`（**仅「学生申请复审」时出现**）；
评分合计在需教师复审时是「**总分 = 各关教师得分之和**」+ 教师总评语 + 保存草稿 / 定稿并结算，
否则只读展示 **AI 逐关得分合计** 与 AI 总评语。顶部还有标星跟进与重跑 AI 评审。

状态 / 及格 / 作答解析等展示口径集中在 `utils/reviewState.ts`，列表与详情共用。

### 与后端同步的口径（编码字段已下线）

后端已把「技能树编码 `tree_code` / 技能点编码 `node_code` / 模块编码 `stage_key`」整体去掉，
唯一性判定也改成按名称，前端已同步：

| 位置 | 现状 |
| --- | --- |
| 类型与请求体 | `SkillTreeRead` / `SkillTreeNode` / `StageTemplate` / `ProjectModule` / `AttemptStageDetail` / `SubmissionStage` 均不再有编码字段；`SkillTreePayload` / `SkillNodePayload` / `StageTemplatePayload` 也不再提交编码 |
| 技能树 / 技能点 | 列表只显示名称；新建与编辑弹窗只有「名称（唯一）」+ 说明 / 状态等业务字段；技能点搜索按名称与说明 |
| 模块库 | 表格只显示模块名；新建与编辑弹窗只有「模块名称（唯一）」+ 默认权重等；项目弹窗里的关卡卡也只显示关卡名 |
| 关卡 | 审核详情与关卡作答统一用 `stage_name`（原 `stage_key` 兜底已删除） |

作答区只渲染学生写的内容：正文里的 `### 小标题` 会被解析出来用**主色加粗**、正文用深色，
长文不再是一整块灰底文本；没有小标题的作答就按整段正文展示（项目侧的「作答要点」不再重复展示）。

状态只有**流程三步**（不把后端 7 个内部状态直接摊给老师看），并且**只有学生提出复审时状态才会变**：

| 页面状态 | 触发条件 |
| --- | --- |
| `AI 已审阅` | AI 出结果即进入（AI 评审生成即定稿并结算），不需要任何人操作 |
| `学生申请复审` | **只有学生提异议**才会变到这里（`objection_reason` 有值 / 后端 `PENDING_REVIEW`、`REVIEWING`） |
| `教师已复审` | 教师定稿并结算后（后端 `REVIEWED`） |

另有流程之外的两个边角：`待 AI 评审`（还没跑 AI）、`学生已撤回`。
及格口径：`final_conclusion` 只由**定稿**的评审写入（AI 定稿或教师定稿），等于 `PASS` 才是及格；
还没有定稿评审时显示「待判定」而不是未及格。教师只写分数，最终结论由系统按项目层级及格线判定——
界面里没有「认领复核」，也没有手填结论的入口。

状态筛选在后端参数之外做了一次前端派生（后端按单个 `status` 过滤，页面上的三步与它并非一一对应）；
学生 / 项目筛选走后端 `student_id` / `project_id`，班级筛选按任教班级花名册在前端过滤。

**教师评分与评语的开放条件**：只有状态为「学生申请复审」时才出现逐关分数输入、教师总评语与
保存草稿 / 定稿并结算；其余状态（AI 已审阅、教师已复审、待 AI、已撤回）一律只读，
只展示学生作答与 AI 评分评语，并在原位置给出说明（教师已复审的分数与评语仍可在「复审与评审留痕」里查）。

关于「定稿 / 草稿」：**AI 评审一经产生就是 `FINAL` 并立即结算**（`POST /submissions/{id}/ai-review`
落库即定稿，演示数据里 16 条 AI 评审全部是 `FINAL`，没有草稿）；只有**教师**评审可以先存 `DRAFT` 草稿，
草稿不结算、不改提交状态。所以界面上不会出现「AI 通过但未定稿」——提交状态 `AI_PASSED` 的含义是
「AI 已判通过、还没教师复审」，与 AI 评审是否定稿是两件事，文案里已写明。

数据映射：AI 的 `dimension_json` 本来就是「每关一维」（`{name: 关卡名, score, weight, reason}`，
例：`需求分析 10/10`），界面按关卡名匹配（容忍 `一、`、`1.` 这类序号前缀，维度数与关卡数一致时再按顺序兜底）；
教师保存时用同一形状写入自己的每关分数与评语，`total_score` 取各关之和。

## 设计约定（与学生端同一套）

配色、圆角、阴影、字体全部集中在 `src/assets/styles/tokens.css`，组件不写死具体数值。

| 项 | 取值 | 用途 |
| --- | --- | --- |
| 主色 | `#1E7BE8 → #1677FF` | 顶栏渐变、主按钮、导航高亮、图表主色 |
| 页面底色 | `#F0F6FF` | 内容区背景 |
| 面 | 白底 + 12px 圆角 + `--sh-1` 轻投影 | 卡片、表格外壳、弹窗 |
| 状态色 | 已完成 `#52C41A` / 进行中 `#FA8C16` / 可挑战 `#1677FF` / 未解锁 `#BFBFBF` | 药丸、进度、分数分档 |
| 标签圆角 | `--r-chip: 4px` | 药丸、标签、按钮（方形为主，只留一点圆角） |
| 数字字面 | `--font-num` + `tabular-nums` | 指标、分数、进度，避免刷新时跳动 |

教师端在学生端的基础上做了三处针对性处理：

1. **顶栏承载身份与指标**：与学生端同款蓝色渐变，左侧校徽，中间教师身份，右侧「任教班级 / 负责学生 / 待复核」三项读数（点击可跳对应页面）；
2. **页面里不再有标题**：内容区直接以卡片开始（页面名只出现在左侧导航高亮与浏览器标签标题里），顶栏也不显示页面名；
3. **左侧导航为一个平铺列表**：七个入口按原型顺序排列，白底 + 蓝色高亮块，底部可收起（偏好写入 `localStorage`）。

### 界面规范（这一版收紧的地方）

| 规则 | 做法 |
| --- | --- |
| 不用图标 | 标题、Tab、按钮、空态一律纯文字，不使用 emoji |
| 卡片不带左侧色条 | 层级只用「字重 + 发丝线」表达；颜色留给状态（药丸 / 分数 / 图表），不做装饰 |
| 指标读数合成一条 | 六项指标收进同一块面板，格与格之间只有 1px 细线（`gap: 1px` + 底色），鼠标悬停时整格铺一层极浅品牌色 |
| 模块用序号代替图标 | 标准化实训模块、分模块评分、AI 各维度都用「1 / 2 / 3…」方牌标识顺序 |
| 危险操作用文字按钮 | 证书规则的「编辑 / 删除」由图标按钮改为文字按钮 |
| 页面里不放标题 | 内容区第一行就是卡片/Tab，不再有「教学管理后台」眉标、页面名与说明副标题 |
| 导航不再分组 | 侧栏七个入口平铺，没有「教学运营 / 教学结果 / 组织与认证」分组标题 |
| 禁用页面回弹 | `html, body { overscroll-behavior: none }`，滚到最顶 / 最底不再有橡皮筋效果 |

保留的三类非装饰符号（都不承担视觉装饰，去掉会影响信息或操作）：

- 左侧导航的线性图标：窄屏收成图标栏时靠它识别入口；
- 难度星级 `★`：它是「1–5 星」的数值展示；
- 关闭 / 移除 `✕`：列表与标签的收尾操作符。

## 数据流

```text
View（views/*.vue）
   ↓ 读取 / 触发
Store（stores/*.ts）          ← 页面状态、跨页共享数据
   ↓ 调用
API（api/*.ts）               ← 接口签名层，接后端只改这里
   ↓ 当前指向
Mock（mock/data.ts + server.ts）
```

接入真实后端：把 `.env` 的 `VITE_USE_MOCK` 设为 `false`，`VITE_API_BASE` 指向网关即可，
`types/` 与页面保持不变。

## 常见改动指引

| 想做什么 | 改哪里 |
| --- | --- |
| 调整配色 / 圆角 / 阴影 / 字体 | `assets/styles/tokens.css` |
| 调整顶栏（身份、指标、操作入口） | `components/AppHeader.vue` |

| 改浏览器标签标题 / 侧栏文案 | `router/index.ts` 的 `meta.title`（只用于浏览器标签标题，页面内不再显示） |
| 改列表 / 表格密度、药丸样式 | `assets/styles/base.css` |
| 增删 Mock 数据 | `mock/data.ts` |
| 维护技能库（体系 / 技能点种子数据与默认点亮口径） | `config/skills.ts`；运行时数据在「岗位与技能体系 → 技能管理」里改 |
| 技能点读写接口 | `api/skill.ts` + `mock/server.ts` 的 `/skill-tags` 三个方法 |
| 改图表配色 | 对应 view 里的 ECharts `option`（ECharts 需要字面量色值，不能写 `var()`） |
